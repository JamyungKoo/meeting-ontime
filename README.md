# meeting-ontime

Google Meet 미팅에 늦지 않게 해주는 로컬 도구.
등록해둔 미팅을 **시작 직전에, 평소 쓰는 실제 Chrome 창으로, 카메라/마이크가
꺼진 상태로** 자동 참여시켜줍니다. 미팅이 시작되면 그 창에서 마이크만 켜면 됩니다.

- 반복 미팅은 **한 번 등록하면 끝** — 매일 캘린더에서 그날의 시간을 읽어와 자동 참여
- 입장 시점은 관리 페이지에서 **정각 / 30초 / 1분 / 2분 전** 중 선택
- 특정 날짜 회차만 **건너뛰기**, 휴가는 **날짜+시간 범위로 중지**
- 관리는 로컬 웹페이지(`http://localhost:5959`)에서 클릭으로

> **AI 에이전트에게**: 사용자가 이 README로 셋업을 요청했다면, 아래
> [🤖 For AI Agents](#-for-ai-agents--셋업-플레이북) 섹션을 따라 셋업부터
> 사용법 안내까지 진행하세요.

### 시작하기

이 폴더에서 [Claude Code](https://claude.com/claude-code) 또는 Codex CLI를 열고
한 줄만 입력하세요:

```
README.md 읽고 셋업해줘
```

에이전트가 설치 → 캘린더 연결 → Chrome 확장 → 실행 검증 → 사용법 안내까지
진행합니다. 중간에 직접 해야 하는 일은 두 가지뿐입니다:

1. Google Calendar에서 **iCal 비공개 주소** 복사해서 전달 (에이전트가 경로를 안내)
2. Chrome에 **확장 프로그램 로드** (에이전트가 경로를 안내)

### 사용법

`npm start`를 켜두면 관리 페이지(http://localhost:5959)가 열립니다.
확장을 설치했다면 Chrome 툴바의 아이콘을 눌러도 열립니다.

페이지는 위에서부터 **오늘 미팅 / 자동 입장 등록한 미팅 / 휴가·자리 비움 /
이번 주 미팅 / 수동 추가** 순으로 구성됩니다.
**자동 참여 등록은 "이번 주 미팅"에서** 하고, "오늘 미팅"은 당일 조작만 다룹니다.

| 기능 | 방법 |
|---|---|
| 매번 자동 참석 (반복 미팅) | 이번 주 미팅 → **[항상]** — 캘린더에 뜨는 날마다 자동 참여 |
| 특정 날짜만 참석 | 이번 주 미팅 → **[1번]** — 그 회차만 참여 (단발 미팅은 이 옵션만) |
| 등록 해제 | **[해제]** 클릭 |
| 이번 회차만 빠지기 | **[건너뛰기]** — 등록은 유지, 그 날만 제외 (등록된 미팅에만 표시) |
| 입장 시점 바꾸기 | 상단 **입장 시점** → 정각 / 30초 전 / 1분 전 / 2분 전 (즉시 반영) |
| 휴가 / 자리 비움 | 날짜+시간 범위 지정 → **그 범위에 시작하는 미팅**만 참여 안 함 |
| 동작 테스트 | 오늘 미팅 → **[지금 접속]** — 즉시 Chrome에서 열림 |
| 캘린더에 없는 미팅 | 하단 **수동 추가** (날짜+시간+Meet 링크) |

동기화 주기: 서버 시작 시 / 날짜가 바뀐 뒤 첫 확인 / **오전 8시~오후 1시엔 1시간마다** /
새로고침 버튼. 미팅이 자동으로 열리면 카메라/마이크는 꺼져 있으니 마이크만 켜고
말하면 됩니다.

### 설정 (.env)

| 키 | 기본값 | 설명 |
|---|---|---|
| `ICS_URL` | (필수) | 캘린더 iCal 비공개 주소 |
| `LEAD_SECONDS` | `60` | 미팅 시작 몇 초 전에 열지. **관리 페이지의 '입장 시점'을 고르면 그 값이 우선**하고 이 값은 폴백이 된다 (되돌리려면 `rules.json`의 `settings.leadSeconds` 삭제) |
| `AUTO_JOIN` | `true` | `false`면 참여 버튼은 안 누르고 대기 화면까지만 |
| `PORT` | `5959` | 관리 페이지 포트 |

### 주의사항

- **iCal 비공개 주소는 비밀 URL** — 링크만 알면 캘린더를 볼 수 있으니 유출 금지.
  유출 시 캘린더 설정에서 "재설정"으로 갱신. `.env`는 커밋되지 않습니다.
- macOS + Google Chrome 전용 (`open -a "Google Chrome"` 사용).
- `npm start` 터미널이 실행 주체 — 꺼지면 자동 참여도 멈춥니다.

## 🤖 For AI Agents — 셋업 플레이북

**당신(에이전트)이 이 섹션의 실행 주체입니다.** 사용자가 "셋업해줘"라고 했다면
아래 단계를 순서대로 수행하세요. 각 단계에 검증 방법이 있으니 통과를 확인하고
다음으로 넘어가세요. 사용자에게 직접 요청해야 하는 항목은 **[사용자 액션]**으로
표시되어 있습니다.

### 아키텍처 (수정·디버깅 시 참고)

```
┌───────────────────┐
│ Google Calendar   │
└─────────┬─────────┘
          │  ICS_URL로 fetch
          │  (서버 시작 시 / 날짜 변경 후 / 8~13시 1시간마다 / 새로고침)
          ▼
┌─────────────────────────────────────────────────────────────────┐
│ Node 서버  (npm start)                                          │
│                                                                 │
│  관리 페이지 :5959 - 등록 / 건너뛰기 / 휴가 / 입장 시점         │
│        └ 변경분은 rules.json에 저장 (재시작 없이 반영)          │
│                                                                 │
│  입장 시점 = rules.json의 settings.leadSeconds                  │
│              └ 없으면 .env의 LEAD_SECONDS (폴백)                │
│                                                                 │
│  그 시각이 되면:                                                │
│  open -a "Google Chrome" <meet-url>?ontime=1&ontime_join=1      │
└────────────────────────────────┬────────────────────────────────┘
                                 │  (ontime_join은 AUTO_JOIN=true일 때만)
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ Chrome 확장 (extension/)                                        │
│                                                                 │
│  content.js      ?ontime=1 탭에서만: 캠/마이크 OFF → 참여 클릭  │
│  background.js   툴바 아이콘 클릭 → 관리 페이지(:5959) 열기     │
└─────────────────────────────────────────────────────────────────┘
```

| 파일 | 역할 |
|---|---|
| `src/engine.js` | 동기화·스케줄 판정·등록/건너뛰기/휴가/입장 시점 로직 (핵심) |
| `src/ics.js` | ICS 파싱, RRULE 전개, Meet 링크 추출 |
| `src/server.js` | 관리 페이지 + REST API (`/api/state`, `/api/settings` 등) |
| `src/chrome-open.js` | 실제 Chrome으로 Meet 열기 |
| `extension/content.js` | Meet 탭 안에서 음소거+참여 (`data-is-muted` 토글) |
| `extension/background.js` | 툴바 아이콘 클릭 → 관리 페이지 열기 (포트 하드코딩) |
| `extension/icons/` | 확장 아이콘 (`icon.svg`가 PNG들의 원본) |
| `rules.json` | 등록 규칙 + 건너뛰기 + 휴가 + **전역 설정**(`settings.leadSeconds`) |
| `state.json` | 접속 이력 (중복 접속 방지) |

> **설정 출처가 두 곳**입니다: 입장 시점은 `rules.json`의 `settings.leadSeconds`가
> `.env`의 `LEAD_SECONDS`보다 우선합니다. `.env`를 고쳐도 안 바뀌면 이걸 확인하세요.
> (`rules.json`/`state.json`은 자동 생성, 커밋 제외)

### Step 1 — 설치

```bash
npm install
```

전제: macOS, Google Chrome 설치, Node 18+. 의존성은 `dotenv`, `node-ical` 2개뿐이라
수 초면 끝납니다.

### Step 2 — 캘린더 연결 (ICS_URL)

1. `cp .env.example .env`
2. **[사용자 액션]** 사용자에게 다음 경로를 안내하고 주소를 받아오세요:
   - 캘린더 → ⚙️ **Settings** → 왼쪽 **"내 캘린더의 설정"** → **본인 사용자 이름** 클릭
   - **"iCal 형식의 비공개 주소"(Secret address in iCal format)** 복사
     (⚠️ "공개 주소" 아님 — 올바른 형식: `.../ical/<이메일>/private-<토큰>/basic.ics`)
   - 바로가기: https://calendar.google.com/calendar/r/settings
3. 받은 주소를 `.env`의 `ICS_URL=`에 넣으세요.
4. **검증**: `curl -s -o /dev/null -w "%{http_code}" "<ICS_URL>"` 이 `200`이어야 합니다.
   - `404`면 십중팔구 공개 주소(`/public/`)를 복사한 것 → 비공개 주소로 다시 안내

### Step 3 — Chrome 확장 설치

**[사용자 액션]** 사용자에게 안내하세요:

1. Chrome에서 `chrome://extensions` 접속
2. 우상단 **개발자 모드** ON
3. **"압축해제된 확장 프로그램을 로드"** → 이 프로젝트의 `extension/` 폴더 선택

설치하면 툴바에 아이콘이 생기고, 클릭하면 관리 페이지가 열립니다.
`.env`의 `PORT`를 바꿨다면 `extension/background.js`의 `DASHBOARD_PORT`도 같이
고쳐야 합니다 (확장은 `.env`를 읽을 수 없습니다).

참고: 이후 `extension/` 코드를 수정하면 반드시 확장 새로고침(⟳)을 안내해야
합니다 — Chrome이 content script를 캐시합니다.

### Step 4 — 실행 및 검증

```bash
npm start
```

관리 페이지(http://localhost:5959)가 자동으로 열립니다. 서버는 계속 떠 있어야
하므로 백그라운드로 실행하거나 별도 터미널을 안내하세요.

**검증**:
```bash
curl -s http://localhost:5959/api/state
```
- `lastError`가 `null`이고 `meetings` 배열에 사용자의 실제 미팅이 있으면 성공
- `meetings`가 비어 있으면: 오늘~7일 내 Meet 링크 있는 일정이 실제로 있는지
  사용자에게 확인
- 포트 충돌 시: `.env`의 `PORT` 변경

### Step 5 — 동작 테스트

**[사용자 액션]** 관리 페이지에서 아무 미팅의 **[지금 접속]**을 눌러보게 하세요
(또는 `node src/cli.js join <meet-url>`).

성공 기준: 실제 Chrome에 Meet 탭이 열리고 → 몇 초 내 카메라/마이크가 저절로
꺼지고 → 참여까지 진행. 탭은 열리는데 음소거가 안 되면 Step 3의 확장 설치/새로고침
문제입니다.

### Step 6 — 사용법 안내

셋업이 끝나면 사용자에게 다음을 설명하세요:

- **"이번 주 미팅"** 섹션에서 참석할 미팅에 **[항상]**(반복) 또는 **[1번]**(1회) 등록
- 등록된 미팅은 설정한 입장 시점(기본 1분 전)에 자동으로 열림 (마이크만 켜면 됨)
- 입장 시점은 상단 **[정각 / 30초 전 / 1분 전 / 2분 전]**에서 언제든 변경
- 회차 제외는 **[건너뛰기]**, 휴가는 **휴가/자리 비움**에 날짜+시간 범위
- `npm start` 터미널을 켜둬야 동작한다는 점

### 트러블슈팅

| 증상 | 원인/조치 |
|---|---|
| 동기화 실패: ICS_URL이 없습니다 | Step 2 미완료 |
| ICS fetch 404 | 공개 주소를 복사함 → 비공개 주소로 교체 |
| 미팅이 안 뜸 | 7일 내 Meet 링크 있는 일정이 없거나, 다른 캘린더의 ICS를 복사함 |
| 탭은 열리는데 음소거/참여 안 됨 | 확장 미설치 또는 코드 수정 후 새로고침(⟳) 누락 |
| 참여 버튼을 못 누름 | Meet UI 문구 변경 가능성 → `extension/content.js`의 `JOIN_RE`에 새 문구 추가 |
| 같은 미팅에 중복 접속 | 정상적으론 `state.json`이 방지 — 파일 삭제 여부 확인 |
| 시간대 이상 | 서버는 로컬 시간 기준 — 시스템 시간대 확인 |
| `.env`의 `LEAD_SECONDS`를 바꿔도 안 먹힘 | 관리 페이지에서 입장 시점을 고른 적이 있으면 `rules.json`의 `settings.leadSeconds`가 우선 — 그 키를 지우면 `.env` 값으로 복귀 |
| 확장 툴바 아이콘이 빈 페이지를 엶 | `.env`의 `PORT`를 바꿨는데 `extension/background.js`의 `DASHBOARD_PORT`가 그대로 |
| 건너뛰기 버튼이 안 보임 | 자동 입장 등록이 안 된 미팅에는 표시되지 않음 (먼저 [항상]/[1번]으로 등록) |
